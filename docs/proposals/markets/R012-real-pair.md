# R012 real_pair: 相場の DB の 1 ペアをそのまま再生し、円の口座で回す

- 種類: 市場モデル / 状態: 実装済み(E016 で使用)
- 実装: `fxsim/markets/models/real_based.py`(登録名 `real_pair` v1)、部品 `PairReplay`(`components/real.py`)・
  `RecordedSpread`(`components/spread.py`)
- 親: R001(real)、E015(ロールオーバーの作り物)

## 仮説
合成の相場は、どう作っても実際の為替の癖(数週間〜数か月のトレンドの塊など)を再現しきれない(S038・E010)。
戦略を実データだけで、しかも 1 本の歴史に頼らずに評価するには、主要ペアと期間を分けて独立に近い実データのパターンを増やす。
そのために、MT5 から溜めた足(相場の DB)の任意のペアを、円の口座の戦略がそのまま回せる形で再生する。

## 設計
`{"source": {"path": "db:EURUSD/H1", "start": "...", "end": "..."}}` のように使う。

| 項目 | 中身 | 理由 |
|---|---|---|
| 円への換算 | 決済通貨が円でないペアは、期間の最初の時点の「決済通貨 1 単位の円の値」K(相場の DB の USDJPY・USD<通貨> から)を価格に掛ける。pip も元の pip x K | エンジン・MT5 のテスター・量の決め方は、価格の差 x 量を円の損益として足す。値動きの比率はそのままで、損益・証拠金・量・pip がそろう。換算は期間の中で固定(期間の最初の値なので先読みは無い) |
| 足の中の順番 | 陽線は 始値 → 安値 → 高値 → 終値、陰線は 始値 → 高値 → 安値 → 終値(MT5 のテスターの 1 分足 OHLC と同じ) | RealReplay は常に高値が先で、損切りと利確が同じ足に入ったときの順番が偏る |
| スプレッド | 足ごとの記録(MT5 の足の中の最小)の、前後 1 本の最大。下限 0.1 pip | 記録は最小なので、ロールオーバーの直前の足が狭いまま残り、その足の終値で約定すると広いスプレッドを払わずに済む(E015)。費用を多めに見る側に倒す |
| スワップ | ペアの金利差(`data/real/short_rates_monthly_fred.csv`、8 通貨の短期金利の月次)。`meta["swap_pair"]` で backtest(`build_backtester`)と戦略(`Bars.pair`)に伝える | 既定の USD − JPY の政策金利は、ほかのペアでは意味が無い。carry_trade は v2 でペアの金利差を読む(ほかの相場では v1 と同じ) |
| シード | 決定的(1 本だけ) | 実データの再生 |

既存の `real`(R001)は変えていない(日足の FRED の CSV で使い続ける)。

## 測り方
`tests/test_pair_eval.py`: 円への換算(K と pip、4 時間足にまとめても同じ)、足の中の順番、スプレッドの前後の最大、
ペアの金利差のスワップ、carry_trade の金利差。評価そのものは E016。

## 限界
- 円への換算を期間の中で固定しているので、長い期間ほど円の損益がずれる(USDJPY が 100 → 150 円なら、ドル建ての損益の円の値は 1.5 倍違う)。
  損益の符号と pip の数字は正しい
- 記録のスプレッドの前後の最大は、ロールオーバーの前後 1 本(1 時間足なら 1 時間、5 分足なら 5 分)を広げるだけ。
  指標の瞬間の広がりは、記録(足の中の最小)に出ない限り入らない
- mid は「bid + 記録のスプレッド / 2」。ロールオーバーの瞬間の mid は低く出る(E015)。費用はスプレッドの側で多めに取るが、
  戦略の信号はその mid を見る
- 1 時間足・日足は足の中の経路を持たない(4 点)。損切り・利確はその 4 点と点の間のブラウン橋で判定する
