# E050 損切り・利確・入り方の組み合わせで、押し目は費用を越えるか

- 種類: 実験 / 状態: 完了(2026-11-13)
- 実装: `fxsim/research/exit_grid.py`(格子と、でたらめな入りとの比較)、`fxsim/research/pullback_limit_engine.py`
  (本物のエンジンで通しで回す)、戦略 S049 `main_pullback_limit`、エンジンの修正(待機注文にもスワップの向きの決まり)
- 動作ケース: B064(指値 ATR x 0.5、両方向)、B065(成行の対照)、B066(受け取る向きだけ)
- 親: E048(押し目 B060)、E049(日中では負ける)、E007(損切りの期待値は 0)

## 問い
利用者の依頼(2026-11-13): 損切りと利確の釣り合いをいろいろ試して、うまくいく形を探す。アルゴリズムの売買ならではの強みは無いか。

## 設計(回す前に決めた)
- 信号は日足の押し目(S048 のまま)。約定は 1 時間足の bid の高安で 1 時間ごとに追う(主要 10 ペア、2010-10〜2026-11)
- 格子 336 通り: 入り(成行 / 指値 ATR x 0.25・0.5・1.0、24 時間有効)x 損切り(ATR x 0.5〜3、なし)x
  利確(ATR x 0.25〜3、なし)x 信号の出(あり / なし)
- 不利な側に倒す約定: 買いは ask・売りは bid、指値はロールオーバーの前後で約定させない、同じ足で損切りと利確に届いたら
  損切りが先、指値で入った足では利確を見ない
- 対照: 同じ回数で、でたらめな日にでたらめな向きで入る版を 20 通り。格子ごとの平均と振れ(標準偏差)を物差しにする。
  格子から一番を拾うことの補正は、でたらめ 1 通りが格子の中で出す最大の z と比べる
- 発見(〜2018-10)と確認(2018-11〜)に分ける
- 最後に、本物のエンジン(MT5 のテスター、1 時間足の実データ)で pair-eval にかける

- 利確: ATR x 0.25 +0.97 / −0.67、x 0.5 −0.47 / +2.07、x 1 −1.02 / +5.22、x 2 −1.83 / +5.40、なし −2.42 / +5.30
- 損切りは近いほど悪く、遠いか無いのが一番。利確はどの幅でも差が無い(年率 +0.7〜1.5%)。勝率は利確を近くすると
  64% → 91% に上がるが、利益 / 損失の比が 0.59 → 0.11 に下がって差し引きは変わらない
- でたらめな入りでは、どの損切り・利確でも平均 −1.6 bp(費用の分)。損切りと利確は期待値を作らない(E007 と同じ)

- 研究とエンジンは 1 取引ずつ突き合わせて一致を確かめた(USDJPY。成行 +7.1 pip と +8.9 bp、指値 +7.8 pip と +11.0 bp。

  14 回ほどしか無いこと

### 4 エンジンの修正
MT5 のテスターの「スワップを払う向きの新規は出さない」(`swap_side_only`)が成行にしか掛かっておらず、待機注文は通っていた。
待機注文にも同じ決まりを入れた(`request_pending`、テスト `test_swap_side_rule_also_blocks_pending_orders`)。
待機注文を使う 1 ペアの動作ケースはこれまで無かったので、過去の結果は変わらない。

## 判定
1. 損切りと利確の釣り合いは、成績を変えない。でたらめな入りではどの幅でも費用の分だけマイナス、押し目でも差は発見と確認で
   ばらばら。変わるのは勝率と分布の形だけ
2. 効いたのは入り方。押し目に「指値で 1 日待つ」を足すと、でたらめな入りとの差が成行 +1.3 bp から +4.6〜7.4 bp に広がる。
   格子全体の選び直しの分を引いても、でたらめでは出ない大きさ(z 4.96 > でたらめの最大 4.11)。機械で待てることの強みは
   ここにあった
3. それでも公式のテストは通らない。B064 は pair-eval で 5 条件すべて不通過、通しのエンジンでも円の損益は t 0.21。
   採用の候補にはしない
4. 受け取る向きだけに絞る(B066)と悪くなる(素の損益 −7.8 pip / 取引、年 1 回)。押し目は両方向で意味がある型

- 指値の深さ 0.5 は山の頂上(0.25 と 0.75 もプラス)なので、これ以上の細かい調整はしない
