# E061 暦で決まる時刻の癖(五十日の仲値、月末のロンドン 16 時のフィキシング)

- 種類: 実験 / 状態: 完了(2026-11-13)
- 実装: `fxsim/research/calendar_effects.py`
- 親: E015(時間帯の癖は費用を越えない)、INSIGHTS §5(五十日は未検証)

## 問い
利用者の案(2026-11-13): 「日時で AI に判断させて、戦略を分析させる」。

LLM に過去の日付(やその日のニュース)を渡して売買を判断させると、LLM はその日より後の相場を学習で知っているので、
バックテストの成績は全部かさ上げされる。日付を隠しても文面から時期は当たる。`check-lookahead` はコードの先読みしか
見ないので、これは検出できない。正しく測れるのは、モデルの知識の締め切りより後の相場でのフォワードテストだけで、
この場では検証できない(日足で 1 ペア年 250 回なので、小さな優位性の確認には年単位かかる)。

ここでは、この案のうち未来が漏れずにバックテストできる部分、つまり暦の決まりだけで作れる信号を測る。時間帯と曜日は
E015・E048 で測ってあるので、まだ測っていない 2 つ(五十日・月末のフィキシング)をやる。

## 設計(回す前に決めた)
- 相場: 相場の DB(OANDA のデモ口座の足、UTC)。1 時間足 2010-10〜2026-11、5 分足 2025-07〜(五十日の時刻の確認用)
- 五十日: 5・10・15・20・25 日と月末(土日なら前の金曜、日本の祝日は扱わない)。東京の仲値 9:55 JST = 00:55 UTC
  - 買い: 前日 23:00 UTC(8:00 JST)で USDJPY を買い、00:00 UTC / 01:00 UTC / 00:55 UTC(5 分足)で売る
  - 売り: 仲値の後の戻り(01:00 → 03:00 UTC、5 分足は 00:55 → 02:55 UTC)
  - 円のクロス 3 本も同じように測る。対照は五十日でない平日の同じ時刻
- 月末: 月の最後の平日の 16:00 ロンドン(夏時間 15:00 UTC、冬 16:00 UTC)の前後 1 時間の、ドルの向き(対ドル 7 ペアの平均)
  - ドルを買う(無条件)と、月初からのドルの動きの逆に張る(リバランスの代わり。株価のデータが無いのでドル自身の動きで代えた)
  - 対照は月末でない平日の同じ時刻
- 費用: 往復でスプレッド 1 回分(その足の記録の最小のスプレッドなので甘め)
- t は 1 回ごとの損益(月末はペアの平均で 1 回)の平均 ÷ 標準誤差。試した数は五十日 20 通り + 月末 4 通り

```bash
python -m fxsim.research.calendar_effects
```

## 判定
- LLM に日付で判断させる案: 過去の日付では検証できない(学習した未来が漏れる)。締め切り後の期間で試した結果は E066
  (でたらめな向きと区別できない)。日時の特徴だけのモデルは E064
- 五十日: 却下。2018 年より後に素の偏りはあるが、費用込みで 0
- 月末のフィキシングの後のドル買い: 癖は本物(研究の約定で t 3.0、本物のエンジンで帰無との差 t 3.5、隣の日には無い)。
  ただし大きさが小さすぎて、単独では使い道が無い(年 12 回 x 1〜2 bp)。候補表には「小さいが本物の癖」として残す。
  pair-eval の不合格は、取引が無いパターン(ドルを含まないペア・スワップの決まり)が R1 のプラスの割合を下げた形の上のもの

## 次の一手
- 量を 3 倍にした版(B084)は平均が 2.4 倍で、年 0.3% 前後。量を増やしても、使い道が出る大きさにはならない。16 時(ロンドン)前後の実際のスプレッドは、1 分足の記録では測れなかった(上の 4)。デモ口座の常駐(`fxsim trade`)で B083 を動かし、実際の約定のスプレッドを記録して測る(利用者の端末で)
- 株価指数の月中の動き(リバランスの本来の決め手)が手に入れば、前の 1 時間の向きを条件付きで測り直す
