# E004 取引の費用と約定の仕方は、損益のどこを削るか

- 種類: 実験 / 状態: 実行済み
- 設定: `configs/costs.yaml`(10 年 x 8 パターン、市場 3 種 x ブローカー 4 種 x 戦略 6 本)
- 実装: `fxsim/backtest/broker.py`(プリセット fair / ecn / malicious)、`fxsim/backtest/engine.py`(経路での約定・手数料・
  金利差のスワップ・ラストルック・ゼロカット)、`fxsim/data/rates.py` と `data/real/policy_rates_usd_jpy.csv`、
  費用の内訳 `fxsim/backtest/metrics.py::cost_breakdown`
- 関連: M005(異常な値動き)、R007

## 仮説
これまでの費用は「スプレッド + スリッページ + 固定のスワップ」だけで、損切りは足の高安で判定していた。現実には
1. **スワップは金利差で決まり、年によって符号も大きさも変わる**(2008 年までと 2022 年以降は買いで大きく受け取り、
   2009〜2021 年はほぼ 0)。ブローカーは買い・売りの両側から上乗せを取る
2. **手数料**: ECN 口座は生のスプレッドが狭い代わりに、片道ごとに手数料がかかる
3. **損切りは飛んだ先で約定する**。フラッシュクラッシュや窓では、損切り価格よりはるかに不利になる。
   足の高安だけで判定すると、どちらが先に届いたかも分からない
4. 取引相手として悪意のあるブローカーは、スプレッドの上乗せ・有利な注文の拒否(ラストルック)・マイナス残高の請求もする

これらを入れると、同じ戦略の損益は「素の損益 − スプレッド − スリッページ − 手数料 + スワップ」に分かれ、
どの費用が効いているかが戦略によって違うはず(回転の速い戦略はスプレッド、長く持つ戦略はスワップ)。

## 設計
| | fair | ecn | malicious |
|---|---|---|---|
| スプレッド | 市場のまま | −0.2 pip(下限 0.05) | +0.3 pip(下限 0.5) |
| 手数料(片道、1 万通貨あたり) | 0 | 50 円 | 0 |
| スリッページ | 0.1 pip、上下対称 | 0.1 pip + 平均スプレッドの 0.2 倍、損切りは 1.5 倍 | 0.2 pip + 0.5 倍、不利な方向だけ、損切りは 2.5 倍 |
| スワップ(金利差 −/+ 上乗せ) | 年率 0.25% | 年率 0.25% | 年率 1% |
| ストップ狩り / ラストルック | なし | なし | 35% / 30% |
| ゼロカット | あり | あり | なし |

- 約定はすべて `intrabar="path"`(足の中の基準解像度の経路で、最初に越えた点で判定)。比較のため `fair_bar` は足の高安だけで判定
- 越えた 1 歩が飛び(その足の 1 歩の |動き| の中央値の `gap_k`=6 倍、正規なら約 4σ を超える)のときだけ、飛んだ先の価格で約定する。
  ふつうの 1 歩なら損切り価格で約定する

### 作っている途中で見つけて直した落とし穴
最初の版は、飛びかどうかに関係なく「最初に越えた 1 分の点の価格」で約定させていた。相場は点と点の間も連続して動くのに、
1 分の刻みの分だけ毎回滑る(ランダムウォークでも損切り 1 回あたり平均 0.86 pip。正規の歩幅 σ に対して約 0.58σ の
飛び越し)。その結果、足の高安だけで判定する fair_bar の方が、経路で判定する fair より bollinger で 30 万円以上得をする、という
逆転が起きた(1 回目の E004)。飛びの 1 歩だけを窓として扱うように直し、ランダムウォークでの滑りは 0.05 pip になった
(`tests/test_costs.py::test_stop_fills_at_the_stop_when_the_price_moves_continuously`)。
- スワップは毎日 22:00 UTC に、前日の終値 x 数量 x (向き x 金利差 − 上乗せ) / 365。水曜は 3 日分
- 政策金利の表は手入力の概算(`data/real/README.md`)。正確な値が要るときは FRED の DFF と日銀の公表値に差し替える

## 測り方
```bash
python -m fxsim run configs/costs.yaml
python -m fxsim report <run>
```
- 費用の内訳が足し算で合う(素の損益 − 費用 = 取引の損益)
- fair と fair_bar の差が、急変のある malicious では大きく、急変を外した malicious_calm では小さい
- ecn は回転の速い戦略で fair より損、malicious はすべての戦略で最も損

## 判定
- **費用の内訳は足し算で合う**(表の各行: 素の損益 − スプレッド − スリッページ − 手数料 + スワップ = 損益)
- **経路での約定は、損切りを使う戦略ほど効く**。fair と fair_bar の差は bollinger で 17〜22 万円、donchian で 11 万円、
  利確と損切りが対称な random_entry ではほぼ 0。差の出どころは、1 分の中の本物の飛び(裾の厚い動き・指標・急変)と、
  スプレッドが広がった瞬間に bid / ask 側の損切りが刺さる分(足の平均スプレッドではなく、その瞬間のスプレッドで決済される)
- **異常な値動き(malicious と malicious_calm の差)は、戦略によって向きが違う**。逆張りの bollinger は +10 万円前後得をし
  (急落の後の戻りを拾う)、random_entry は 4〜6 万円損をする。順張りの ma_cross は +5 万円前後
- **ecn は手数料(往復 1 pip 相当)で、回転の速い戦略ほど fair より損**(bollinger で −27 万円)
- **malicious ブローカーは、どの戦略でも fair より 20〜70 万円悪い**。主役はスリッページ(不利な向きだけ・スプレッドに比例)と
  ストップ狩り(10 年で 40〜210 回)。日足の戦略ではスワップの上乗せ(年率 1%)が一番効く
- 判定: 費用のモデルとして採用。fair_bar は比較のための設定として残す
