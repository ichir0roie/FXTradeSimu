# E041 スワップ狙いの建玉に、利確の指値をサーバーに置く

- 種類: 実験 / 状態: 完了(2026-11-12)
- 実装: `main_carry_breakout` の `tp_order`(`fxsim/strategies/main/carry_breakout.py`)、`PortfolioContext.target` の `tp`、
  比較 `fxsim/research/carry_tp_order.py`(約 5 分)、動作ケース B057・B058
- 親: S040(B049)、E034(利確の刻み)、E037(B054)

## 問い
利用者の判断(2026-11-12): 検証のための常駐でも、リスク管理の基本として建玉に利確の指値を置く。
B049 には利確が無く(反対側の 5 日のチャネルを終値で割ったら翌朝に成行で出る)、B054 の利確は終値で判定して翌朝に成行で出す。
どちらもサーバーには急変用の遠い逆指値(ATR x 9)しか無い。建てると同時に利確の指値を置く形にして、成績を崩さない幅はどこか。

## 設計(回す前に決めた)
- `tp_order: true` なら、新規と同時に建値 ± 建てた判断の足の ATR x `tp_atr` に指値を置く。足の中で触れたら利確
  (終値の判定はしない)。シミュレーションでも常駐でも同じ(常駐は新規の注文に tp の幅を付ける)
- サーバーで閉じた建玉は、次の足で戦略が見つけて(`_server_closed`)、指値の利確なら数え、`reenter` なら入り直しを待つ
  (E034 と同じく、反対側のチャネルを割るまでは高値抜けを待たずに入り直す)
- 既定は `tp_order: false`。B049 の結果は前と 1 円も変わらない(表の 1 行目が E037 の 1 行目と同じ)
- 振る値: B049 に ATR x 1・1.5・2・3・5 x 入り直す(なし・あり)、B054 は終値の利確(今)と、指値 ATR x 0.5・1・1.5・2(入り直す)
- 相場・口座・点数は E026 と同じ。選ぶ条件: 点数(直近の実データとランダム 8 本のシャープの平均)が元と同じか上で、
  最大 DD が悪くならないもの

## 判定
1. 指値を近くに置くほど悪い(B049 + ATR x 1 は点数 +0.58 → +0.40)。足の中のひげで利確し、伸びる建玉を早く降りる。
   入り直すと取り戻す(x 1 で +0.54、x 1.5〜2 で +0.59)
2. B049 には ATR x 2・入り直すを置く(B057)。点数は元と同じ(+0.59 対 +0.58)、直近の実データは良く(+0.67 対 +0.60)、
   古い実データ・ランダムは少し低い(+0.62 対 +0.65、ランダムの中央 +0.51 対 +0.56)。最大 DD は同じくらい。
   利確は年 0 → 5 回ほど。差はノイズの幅の中なので、成績のための変更ではなく、指値を置いても崩れないことの確かめ
3. B054 の利確を指値にするなら ATR x 2(B058)。終値の ATR x 0.5 を指値の x 0.5 にそのまま替えると一番悪い
   (点数 +0.30、ロスカット 1 回、古いランダムの最悪の DD 94%)。x 2 は点数 +0.41 で元(+0.39)と同じくらい、
   直近の最大 DD 58% → 46%。代わりに直近 1 年の取引は週 2.0 → 1.1 回、利確は週 1.4 → 0.6 回に減る
4. デモ口座の常駐 2 本(`demo-majors-b049`・`demo-majors-b054`)を B057・B058 に切り替えた(名前・magic・状態の置き場所はそのまま)。
   すでに建っていた 3 本(B049 の USDCHF、B054 の USDCHF・USDCAD、2026-11-12 09:00 JST に約定)には、常駐を止めて
   新規と同じ幅(実際の建値 + 建てた足の ATR x 2)の指値を手で足した(USDCHF 0.84505、USDCAD 1.43883)。
   常駐は「シミュレーションの指値の値段が前の足から動いたとき」しか建玉の指値を直さないので、切り替えだけでは付かない

## 次の一手
- 常駐で指値の利確が起きたら、シミュレーションの利確(足の中で触れた)と実口座の約定の値段・時刻を突き合わせる(E040 の集計と同じ形)

  シミュレーションの今の建玉の損切り・利確を実口座に写し直す操作を足す
